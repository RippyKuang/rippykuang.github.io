## 1. 引用能做，指针做不了的事情

来自周刊群 jajuju。

一直都有“引用是指针的语法糖”的说法，言下之意就是引用能做的，指针一定能做。真的是这样吗？

这个提案讲了，constexpr 函数如果只取了参数的类型信息，那么就算传了变量也可以编译期计算。但是，只能接受引用，不能是指针。

该提案已合入标准，编译器足够新就能用。

于是我们可以完成下面的操作：

```cpp
#include <cstddef>

template <typename T, size_t N>
constexpr size_t array_size(T (*)[N]) {
    return N;
}

template <typename T, size_t N>
constexpr size_t array_size(T (&)[N]) {
    return N;
}

void check(int const (*param)[3]) {
    // constexpr auto s = array_size(param);  // error: 'param' is not a constant expression
}

void check(int const (&param)[3]) {
    constexpr auto s = array_size(param);
}
```

### 理论分析与常量求值证明

为什么指针在常量表达式上下文（Constant Evaluation Context）中会失效，而引用可以正常工作？我们用严格的代数类型系统与渐进复杂度来定义：

在编译期静态分析模型中，对于泛左值引用 $r \in \mathrm{Ref}(T[N])$，编译器对类型性质的投影操作为：

$$ \Pi_{\mathrm{dim}}(r) = N \in \mathbb{N}, \quad \text{Complexity} = \mathcal{O}(1) $$

由于该推导只依赖于类型的静态签名，不涉及对内存物理地址的任何 `lvalue-to-rvalue` 取值：

$$ \mathrm{Eval}_{\text{constexpr}}(\Pi_{\mathrm{dim}}(r)) \equiv N $$

相反，当形参声明为指针 $p \in \mathrm{Ptr}(T[N])$ 时，由于指针对象自身具有独立的状态空间与地址不确定性，在没有明确常量初值的前提下：

$$ \mathrm{Deref}(p) \longrightarrow \bot \quad (\text{Ill-formed in constant expression}) $$

因此，引用在此处展现出了指针完全无法替代的一阶语义特权。
